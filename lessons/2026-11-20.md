### Recall — Module C in six lines
1. Realized return x ~ φ(μ − σ²/2, σ²/T). μ is arithmetic, μ − σ²/2 is compound (Day 17).
2. σ̂ = s/√τ from historical log returns, standard error σ̂/√(2n) (Day 18).
3. A Δ-hedged portfolio is riskless, so it earns r. That gives the BSM equation ∂f/∂t + rS f_S + ½σ²S² f_SS = rf, with no μ (Days 19–20).
4. Risk-neutral valuation: f = e^{−rT}Ê[payoff], which gives c = S₀N(d₁) − Ke^{−rT}N(d₂) (Day 21).
5. N(d₂) = risk-neutral exercise probability; N(d₁) = delta (Day 22).
6. Implied vol is backed out from prices; dividends lower S₀ by their PV (Day 23).

### Today's concept
*Hull: "Binomial Trees" (the BSM limit) and "The Black–Scholes–Merton Model" — the whole chapter. Use today to consolidate.*

**One option, three methods, one price.** S₀ = 100, K = 105, r = 4%, σ = 25%, T = 0.75.

| Method | Idea | Result |
|---|---|---|
| **1. Binomial tree** (Week 2) | Δ-hedge step by step, u = e^{σ√Δt}, let n → ∞ | n = 500: 7.7905; n = 501: 7.7827; average **7.7866** |
| **2. PDE** (Days 19–20) | Solve ∂f/∂t + rSf_S + ½σ²S²f_SS = rf with f(S, T) = max(S − K, 0) | Solution is the BSM formula: **7.7865** |
| **3. Risk-neutral expectation** (Days 5, 21) | e^{−rT} × average payoff with μ = r | 10⁶ paths: **7.791 ± 0.014** |

They agree because they are the *same idea* in three forms. The hedge removes risk, so the price can't depend on μ, so we may as well price in a world where μ = r:
- the tree is that idea in discrete steps,
- the PDE is that idea written as an equation,
- the expectation is that idea written as an average.

**When to use which (practitioner's view).**
- **Formula / PDE:** European calls and puts. Instant and exact.
- **Tree:** American options, which need an early-exercise check at each node (Day 7). American put here (n = 500): **10.12** vs European **9.69**.
- **Monte Carlo:** payoffs that depend on the whole path (Asian or barrier options, Module G) or on many assets. Slow, but flexible.

**The one wrong way.** Discount the *real-world* expected payoff (μ = 12%) at r and you get ≈ **11.28**, way off. This is the mistake from Days 3–5 in its continuous-time form.

**Code** (all three in one place):
```python
import numpy as np
from math import log, sqrt, exp, erf
N = lambda x: 0.5*(1 + erf(x/sqrt(2)))
S, K, r, sigma, T = 100, 105, 0.04, 0.25, 0.75
d1 = (log(S/K) + (r + sigma**2/2)*T)/(sigma*sqrt(T)); d2 = d1 - sigma*sqrt(T)
formula = S*N(d1) - K*exp(-r*T)*N(d2)
def tree(n):
    dt = T/n; u = exp(sigma*sqrt(dt)); d = 1/u; p = (exp(r*dt) - d)/(u - d)
    f = np.maximum(S*u**np.arange(n, -1, -1)*d**np.arange(0, n+1) - K, 0)
    for _ in range(n): f = exp(-r*dt)*(p*f[:-1] + (1-p)*f[1:])
    return f[0]
rng = np.random.default_rng(42)
ST = S*np.exp((r - sigma**2/2)*T + sigma*sqrt(T)*rng.standard_normal(1_000_000))
print(formula, (tree(500) + tree(501))/2, exp(-r*T)*np.maximum(ST - K, 0).mean())  # 7.787  7.787  7.791
```

> **Common pitfall.** Thinking you need different models for "trees", "PDEs" and "Monte Carlo". They're three *numerical methods* for one model (GBM plus no-arbitrage). If two of them disagree by more than their numerical error, there's a bug.
